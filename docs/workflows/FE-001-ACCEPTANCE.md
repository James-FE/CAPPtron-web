## 实现与业务边界

- `AppShell` 组合顶部区域、共享流程导航、文件栏、正文和底部说明，不依赖示例文件名。
- `ModelInputPage` 组合文件选择区和输入准备区；React 状态由 `useModelInput` 管理。
- `ModelSelection` 区分 `empty`、`local` 和 `demo`。仅 `local` 持有当前浏览器的 `File`；Demo 是独立元数据 Fixture，不虚构文件内容、体积或服务器标识。
- 文件选择、更换与拖放使用相同校验，支持 STEP/STP 大小写扩展名。取消或无效输入保留有效选择，不设置任意文件大小限制；不持久化 File，不发起上传或解析请求。
- 后续阶段、数据底座和解读入口仅弹出可关闭的功能说明，支持鼠标和键盘；这些按钮的作用是解释不可用状态，不执行导航或推进业务。
- 没有新增依赖；没有实现工艺决策、程序审核、Agent、数据底座、STEP 几何或 CAM 功能。

## 视觉对照与有意差异

初版按照 Figma 原尺寸实现后，维护者反馈字号偏大、空间比例拥挤，授权调整视觉密度。当前版本保留 r06 的深色配色、三阶段导航和左右结构，按此反馈精修，不再以原型字号和尺寸完全一致为目标：

- 顶部标题 20px、页面标题 26px、选择区标题 20px、准备区标题 17px，正文与控件主要使用 13–14px，辅助说明 12px。
- 流程按钮由 56px 收至 44px，文件栏由 64px 收至 52px；示例入口改为轻量描边按钮，让文件选择成为主要视觉焦点。
- Shell 最大宽度 1840px，正文最大宽度 1440px，左右列约 1.8:1；选择区居中排布，右侧分行展示类别与状态，以细分隔线建立层级。
- CSS Grid/Flex 承担布局，1440×900 保留两列和可读字号，通过外边距、列间距与弹性高度适配。长文件名省略显示，悬停可查看全名，必要时允许纵向滚动。

本轮精修仅调整样式与验收说明，文件选择、Demo 来源、错误反馈和未实现入口的业务行为保持原有约定。最终视觉取舍仍由维护者在真实浏览器中验收，不冻结截图基准。

前端业务状态处理：

- “尚未上传 / 预览完整流程”改为“尚未选择 / 示例仅演示输入状态”，因为本轮未实现上传和后续页面。
- 文件选择提示明确支持格式与本地状态；选中后展示真实文件名、体积和扩展名。
- 输入准备三项增加“待选择 / 待提供 / 待接入”等实际状态；Demo 不宣称已经核实甲方工艺卡片来源。
- 底部补充输入准备与 CAM 的区分，保留人工确认不等于仿真/实机验证的边界。
- 未实现入口增加交互反馈；未把原型的条件跳转实现成虚假的业务完成。

字体优先使用本机 Noto Sans SC，其次 Noto Sans CJK SC、微软雅黑、苹方和系统无衬线字体。CI 安装 Ubuntu 的 `fonts-noto-cjk`，保证中文截图可读；应用不引入字体 CDN 或私有字体文件。Windows/CI 操作系统字体回退和抗锯齿可能造成字形、宽度及像素差异；需要维护者在目标部署环境复核，当前不冻结视觉快照。
