# 原三阶段原型的 Core 真实流程

## 已批准的范围

在原“模型输入 → 工艺决策 → 程序审核”导航和样式中接入 Core，不再跳转独立技术工作区。真实模式复用模型选择器、工序列表/详情、参数字段和 NC 编辑器。已有 Demo 保留并明确标识；真实失败不会加载演示方案或合成成功。

本批实现 STEP 上传、NX 解析状态、绑定解析证据的任务创建、模板规划、离散参数修订、当前工艺卡批准、CAM 启动和当前 NC 完整只读查看。NC 修改、NC 批准及下载按钮保留位置但禁用，未冒充完成。人工 NC 评审和制造验收仍是后续独立门槛。

## 配置与输入

部署者设置 `VITE_API_BASE_URL`、`VITE_CORE_INTEGRATION_CONFIG_URL` 与 `VITE_CORE_INTEGRATION_CONFIG_SHA256`。任一配置项存在即默认进入真实原型；清单地址或摘要缺失会明确阻塞。两项均未配置时可保留 Demo，用户也可显式切换真实流程并看到配置阻塞。

期望摘要来自受控发布记录；加载器核验响应原始字节，不信任同地址动态返回的摘要，不内置历史 Golden 版本作为兜底。配置匹配失败不开放 CAM。

文件选择只记录本地文件，用户显式点击“上传 STEP”才写入 Core，再显式执行解析。外径、内径、厚度和固定倒角/2024 材料展示属于人工目标声明，不是浏览器测得尺寸或已验证材料。任务请求使用尺寸及倒角声明；材料展示不冒充已向后端提交材料字段。解析成功后按 STEP 摘要选择唯一部署模板。解析回执的 report_sha256 是传输文件摘要，不与工程报告摘要直接比较；规划后的 matching_evidence 仍必须与部署配置一致，最终工程准入由 Core 决定。

## 版本、恢复与执行门槛

- `CoreWorkflow` 为真实命令的单一入口。页面不直接访问 Windows、Mastercam、SSH 或 IPC。
- 原任务、结果、修订、工序、工步和文件身份均来自 Core。展示顺序使用服务端 sequence。
- 只对元数据与参数规则共同允许的离散值开放原参数字段。草稿按任务和修订持久化，未提交草稿阻止批准和 CAM；修订请求携带当前版本、反馈版本及模板/计划摘要。
- 工艺卡批准不表示 NC 批准。CAM 前重新查询当前任务、批准归档、执行 profile 和已有活动运行。
- 解析、规划和 CAM 轮询每两秒只执行查询。自动恢复不重发写请求。超时或未知结果保留原 `command_id`、请求体与审核人；用户“重试原命令”才明确重试。上传重试必须匹配原文件名、大小及 SHA-256。
- 确定的结构化 Core 拒绝可通过显式按钮解除并刷新；不可恢复任务或损坏存储会阻塞，不自动创建替代任务。
- 刷新真实原型后查询持久化定位，并回到已有任务或 CAM 的对应阶段；支持展开“恢复已有任务”手动查询任务。
- 只有当前修订 CAM 已完成、当前候选身份匹配且全部 NC 正文读取成功才展示只读程序。读取错误或未决命令时隐藏正文，避免显示部分成功或过期版本。

## 验证与证据边界

组件 HTTP 替身测试覆盖配置失败、只读恢复不发写请求、全部 NC 文件、文件读取失败、旧修订隔离和任务读取失败。控制器已有测试覆盖版本竞争、命令幂等重试和后端门槛。浏览器测试需在 1920×1080 和 1440×900 检查原三阶段、上传失败、参数修订、批准、CAM 与 NC/刷新恢复。

这些是前端工程与契约证据。本批没有执行新的真实 Windows/NX/Mastercam 试验，不证明上传几何驱动加工、NC 人工验收或实机制造通过。
