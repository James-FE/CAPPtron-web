## 工作台与编辑器

三阶段 `input | planning | review` 均可导航，顶部导航只表示页面位置，不代表工艺、CAM 或审核完成。FE-002 CTA 改为“查看参考程序并进入审核”，保留原有全部 Demo 必填格式校验；未加载方案及无正文均有明确空状态。生产部署仅提供案例元数据与不可用说明，不要求用户上传 NC。

选用 CodeMirror 6 的 `state`、`view`、`commands` 最小模块，提供行号、多行编辑、键盘导航、复制粘贴、撤销重做和纵横滚动，不启用自动折行、语义诊断或补全。原生 textarea 难以同时可靠维护外部修订应用和编辑历史；Monaco 的语言服务与工作线程超出本轮需要。审核页面按需加载，编辑器与差异模块不会进入输入页首屏依赖路径。构建审核分包约 289 kB，gzip 约 95 kB。

快捷键为 Ctrl/⌘ Z 撤销、Ctrl/⌘ Shift Z 重做，也保留 CodeMirror 的平台默认快捷键；按钮可执行相同操作。恢复原文和已保存内容都经过统一修改入口，仍是新修订。重新进入页面保留正文、保存基点和修订，编辑器自身的撤销栈在页面重建后重新开始。

`diffLines` 按行显示原始程序与当前草稿的增加/删除，设计算时间上限；超时显示完整双份文本供对照，不冻结界面。编辑器、差异、历史记录、Agent 对话分别局部滚动。

2026-10-20 根据维护者反馈，将“展开代码”改为占满浏览器工作区的专注编辑视图：隐藏品牌栏、三阶段导航、模型栏、审核页大标题、详细来源/历史及外层页脚，移除大块边距；在紧凑工具栏保留资产/版本、草稿修订、保存状态、编码/换行、来源和审核状态，底部保留保存/确认/下载及演示边界说明。代码字号仍为 14px、行高 24px。

可点击“退出专注编辑”或按 Esc 恢复完整布局；编辑器不重新挂载，因此正文、修订、选区和撤销/重做栈延续。Agent 通过工具栏入口打开同一个抽屉，浮动气泡在专注视图隐藏，退出后恢复原位置；关闭 Agent 抽屉或审核对话框不会同时退出专注编辑。布局直接依据页面展开状态生效，不保存跨任务的全局显示开关。

## 程序文档与共享会话

边界为 `ProgramContentReader → ProgramDocument → ProgramEditor → ProgramReviewPage`。

- `useWorkflowSession` 从 FE-002 提取原会话逻辑，由 `WorkflowWorkspace` 持有。每个模型来源生命周期有独立随机 scope，任务身份包含该 scope 与方案身份；工程参考方案身份沿用案例 ID、版本、内容摘要。
- 同一会话保存方案、选中工序、字段草稿、演示进度、Agent 历史及未发送输入，同时只保存一份 `ProgramDocument`。切换到输入/工艺再返回不会丢正文；更换有效模型来源会销毁旧工作台。取消选择或无效文件不清空原任务。
- 文档保存案例、版本、内容摘要、ProcessPlan ID、ProgramAsset ID、来源文件字节摘要、编码/换行、原文、当前草稿、最近会话保存内容和修订号。
- `applyProgramChange` 接受文档 ID、任务身份、预期修订、完整替换文本、`human | agent` 来源及原因。检查身份和修订后递增修订并清除确认；相同文本无变化。旧修订抛出明确冲突，不能静默覆盖。
- `saveProgramDraft` 只更新本次 React 内存会话的保存基点；恢复保存内容不会回退修订号。无服务器保存、刷新恢复或数据库持久化。原始加载不冒充用户已显式保存。根据维护者反馈，界面按钮简化为“暂存草稿”和“恢复暂存”，暂存状态明确提示“刷新后丢失”，含义与原有会话内快照一致。
- 修改记录只记录修订、来源与操作原因，不建设事件溯源系统。原始内容和本次差异可直接查看。

案例读取和程序读取均防止迟到响应串入新任务；程序读取使用 AbortController，应用时再次检查任务身份。

## 本机私有资产读取

维护者在忽略的 `.env.development.local` 设置 `CAPPTRON_GOLDEN_B7_NC`，值为该唯一文件的绝对路径；示例文件只保留变量名，不包含任何私人路径。配置后重启开发服务。删除配置即可关闭。禁止使用会公开给客户端的 `VITE_` 前缀。

`dev/localReference.ts` 仅在 `serve`、`development`、非 preview 时注册端点：`<BASE_URL>__local_reference/golden-b7`。无上传或文件目录服务，不接受路径、资产参数或查询字符串。Vite 端读取现有 v2 元数据，原始字节大小与 SHA-256 均匹配后才返回；浏览器 Reader 再核验并严格解码。`metadata_only` 描述公开案例包的可用性；本机经验证的正文作为独立能力附加，不回写案例契约。

安全边界：

- 配置私有文件时拒绝非 loopback 监听地址。请求还需来自 loopback socket、使用明确本机 Host、同源 Origin/Sec-Fetch-Site 和专用请求头，只允许 GET。
- 跨源、缺少请求标识、POST、任意路径查询返回 403；不存在/未配置不提供正文；大小或摘要不匹配返回 409；异常响应不含文件路径。
- 私有文件始终留在仓库外，未复制到 public、源码或 dist。`.gitignore` 额外忽略 `.nc` / `.NC`，作为误提交防护；它不能代替代码审查。
- 生产 Reader 在发请求前返回不可用；build 不读取正文，preview 不注册私有中间件。实测 preview 对该 URL 只返回静态 HTML fallback，而非 NC；开发服务对 `.env.development.local` 返回 403。
- E2E 专用端口 5183，以 `--mode e2e` 启动并禁止复用已有开发服务，避免读取维护者配置或与本机日常 5173 服务混用。

同事无文件时仍可查看六工序、历史程序引用、证据与限制，正文不可用；不会静默加载合成程序。

## 人工演示确认与导出

“确认可用”打开明确的演示说明对话框。记录绑定文档 ID、任务身份、程序修订和工艺/现场上下文修订。任何程序修改、恢复文本、未来 Agent 修改或现场草稿变化均清除确认；切换资产/版本创建独立文档，不继承确认。对话框打开后上下文或修订变化，提交被拒绝。

数据填写完整、当前修订被人工演示确认、历史验证证据是三个独立事实；本系统没有“正式制造验证通过”状态。历史记录不会自动批准当前草稿；修改现场条件不会重新生成历史 NC，页面持续提示不一定适配。

只有合法来源且非空的正文能确认或导出。`demo_fixture` 明确不可审核，禁用 NC 下载；无正文不创建空文件。导出前另行确认当前修订，使用 `<caseId>-draft-r<revision>.nc`，从当前草稿构造 Blob，不上传服务器、不调用机床，也不要求用“审核通过”作为加工安全许可。

严格支持 ASCII、UTF-8（含可选 BOM）及带 BOM 的 UTF-16LE/BE；无法严格解码时拒绝而非替换字符。编辑内部统一 LF，导出恢复原来的 CRLF/LF/CR、编码和 BOM。ASCII 草稿若新增非 ASCII 字符、无效 Unicode、混合原始换行则明确拒绝导出；不做有损转码。原文没有换行而用户新增行时使用 LF。格式保留不等于机床兼容性证明。
