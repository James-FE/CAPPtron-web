## TODO-001 输入准备区域接入后端状态

**状态：待依赖，未排期。** 来源：FE-001 模型输入页验收讨论。当前只记录需求，不在 FE-001 中实现后端接入。

### 当前情况与目标

右侧“输入准备”包含“模型 / 图纸”“制造要求”“工艺模板与上游方案参考”三个状态摘要。目前模型状态随本地文件选择或 Demo 切换更新，制造要求与参考来源分别显示“待提供”“待接入”。这些区域是信息展示，不是按钮。

未来接入后端后，三项状态应分别根据当前文件或任务的真实数据自动更新，无需刷新整个页面。用户应能看懂当前进度、缺失信息、失败原因以及下一步可执行的操作。

### 预期行为

- **模型 / 图纸**：区分本地选择、上传中、解析中、解析完成和失败等状态。保留文件来源；本地已选择不能等同于服务器已接收或解析完成。
- **制造要求**：展示待提供、待补充、待确认、已确认等准备状态，并展示后端返回的缺失项或冲突。要求已提供或已确认，不等于模型或工艺已经满足制造要求；后者需要另行定义校核能力与结果依据。
- **工艺模板与上游方案参考**：展示是否关联，以及关联资料的来源、版本和适用性确认状态。“已关联”不能等同于“已验证适用”。
- 有真实可用的录入或关联能力后，再增加“填写要求 / 查看要求”“选择参考 / 查看来源”等入口。模型选择和更换继续复用已有入口，避免重复操作。
- 用文字明确表达状态，可辅以轻量标签；不能仅靠颜色区分，也不把信息区域做成无操作的假按钮。

以上状态是需求示例，不是已经约定的 API 枚举。最终状态集合、转换条件和文案需在接入时与后端契约对齐。

### 接入方案与启动条件

- 先确认后端具备对应的上传、解析、要求管理或模板关联能力，以及经过身份验证与授权的业务接口。各项能力可分批接入，未接入项继续准确标注。
- 后端返回结构化状态、文件或任务标识、修订信息，以及必要的原因和缺失项；前端在 `src/api` 中完成接口调用与展示数据映射，交给现有 `InputPreparationPanel` 渲染。
- 用户提交或关联成功后重新获取状态；异步处理可先采用轮询，在任务结束、切换输入或离开页面时停止。是否使用服务端推送，在明确实时性需求后决定，不提前引入复杂通信设施。
- 依据文件或任务标识及版本隔离响应，取消或忽略过期请求，避免换文件后被旧结果覆盖。Demo、本地 File 和服务器结果始终区分来源。
- 网络错误与业务处理失败分别展示；更新失败时保留已有信息并标明状态可能过期，提供重试反馈，不把通信失败误写成解析失败。
- 刷新页面后的任务恢复方式、轮询频率、接口路径与字段均待接入时确认。不得由浏览器直接访问 Mastercam、Worker 或 CAM SDK。

### 验收要点

- [ ] 三项摘要能独立反映服务端真实状态，进行中的异步任务能够自动更新。
- [ ] 覆盖加载、成功、缺失信息、业务失败、网络异常与重试；不会出现无限轮询或离开页面后继续请求。
- [ ] 切换文件或任务后，延迟到达的旧响应不会覆盖当前状态；Demo 与真实结果不会混用。
- [ ] 资料齐备、人工确认、制造要求校核、CAM 与仿真/实机验证的结论保持区分。
- [ ] 使用可控的接口响应补充单元测试和 Playwright 测试，日常自动化不依赖真实后端；另对真实接口进行联调验收。
- [ ] 1920×1080 与 1440×900 下长状态文本、缺失项、错误信息与新增操作无明显遮挡或溢出，并提供真实浏览器截图。
